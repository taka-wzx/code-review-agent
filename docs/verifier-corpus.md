# Phase 8B Verifier Corpus

Phase 8B turns the Phase 8A data protocol into a bounded, auditable corpus
workflow. It freezes public source identities, candidate provenance, two-person
annotation, adjudication, repository-level splits, and every content hash before
any real-corpus training can start. Phase 8B itself does not authorize model
training; the later Phase 8C amendment authorizes only a synthetic CPU smoke run.

The controlling contract is
[`docs/plans/week8-verifier-training.md`](plans/week8-verifier-training.md), and
the machine-readable plan is `verifier_training/corpus-plan.json`.

## Frozen scope

The pilot uses 29 merged PRs from nine permissively licensed public Python
repositories in the half-open UTC window from 2024-01-01 through 2026-01-01.
Whole repositories are assigned once:

| Split | Repositories | PR target |
| --- | --- | ---: |
| train | `pallets/click`, `Textualize/rich`, `pytest-dev/pytest`, `django/django` | 16 |
| validation | `pydantic/pydantic`, `fastapi/fastapi` | 4 |
| test | `pallets/flask`, `psf/requests`, `encode/httpx` | 9 |

The repository licenses are restricted to MIT, BSD-3-Clause, and Apache-2.0.
The fixed corpus seed is derived from the corpus ID and Phase 8 base commit. A
query-qualified pool is capped at 64 PRs per repository, deterministically
ranked by the seed and canonical `owner/repo#number`, then inspected in that
order until each repository target is filled.

The test repositories are blind to candidate-generation tuning, rubric tuning,
threshold selection, and error-driven model changes. Protected `eval/` and
`eval/holdout/` data are not corpus sources and must not be read by this flow.

## Authorization and retention

The Phase 8B instruction authorizes read-only retrieval of selected public
GitHub PR metadata and unified diffs. It does not authorize GitHub mutations,
paid providers, Finder/API generation, dataset or model downloads, accelerator
use, uploads, or Phase 8C.

Raw objects live only in ignored `traces/week8b-corpus/`, are capped at 512 MiB,
and have a maximum retention of 30 days. They are never committed. Committable
records contain canonical public URLs, immutable revisions, licenses, bounded
sanitized text, hashes, aggregate counts, and zero secret-scan findings. The
sanitized/frozen artifact ceiling is 64 MiB.

## Source admission

Every admitted PR source record binds:

- repository, split, PR number, merged time, and canonical public URL;
- distinct base, head, and merge commit SHAs;
- deterministic selection rank and digest plus a selection-log hash;
- changed-file and line statistics;
- byte length, SHA-256, and content-addressed key for the unified diff;
- SPDX license and a secret-scan report hash with zero findings.

Admission fails closed for generated-only, documentation-only, vendored,
dependency-only, bot-authored, security-embargoed, oversized, missing-revision,
or secret-positive changes. At least one non-generated `.py` or `.pyi` source or
test path is required.

`verifier_corpus.py` is intentionally offline. Acquisition is an operator step;
the module validates the resulting identities and hashes without contacting
GitHub or an LLM.

The 2026-07-19 acquisition completed all nine repository targets. The sanitized
snapshot in `verifier_training/corpus-snapshot/` contains 29 public PR source
records with source-set SHA-256
`4ce49ebfe68cb2d0ebe125f2cbd68f77ea3222a64449fcabedd3d39d2ec56209`.
The ignored raw snapshot is 2,021,424 bytes, well below its 512 MiB ceiling.
Its manifest remains `trainable=false`: no Finder candidates or independent
human annotations were generated by source acquisition.

The adjacent `finder-queue.jsonl` deterministically binds all 29 admitted PRs
to their source-record, merge-revision, unified-diff, and queue hashes. Every
entry is `pending` and capped at 16 candidates. It is an immutable operator
handoff, not evidence that Finder was run.

## Candidate and annotation protocol

Each candidate binds exactly one admitted PR record and its merge revision. Its
finding text, bounded evidence, and bounded tool summaries receive a canonical
content hash; the complete source row receives a second hash. Duplicate content,
unknown PRs, unsafe evidence paths, credential-like text, more than 16 candidates
per PR, or more than 480 total candidates are rejected.

Two different independent annotators label every candidate `keep`, `drop`, or
`uncertain`. Matching non-uncertain labels become final. A disagreement or either
`uncertain` label requires one independent adjudicator whose immutable record
cryptographically cites both source annotation IDs and hashes. Missing labels,
repeated annotators, stale citations, mixed synthetic/real provenance, and
unnecessary adjudication fail closed.

Synthetic records are permitted only as protocol fixtures. A freeze containing
any synthetic final label always reports `trainable=false`.

## Freeze outputs and gates

The deterministic compiler emits:

- final Phase 8A-compatible candidate JSONL;
- a whole-repository split manifest;
- a freeze manifest with input/output hashes, counts, agreement/adjudication
  counts, represented repositories, incomplete gates, and `trainable`.

`trainable=true` is possible only when every selected PR has at least one
candidate, every candidate resolves to a final real label, every planned
repository is represented, and no gate remains. A manifest with missing Finder
candidates or human annotations is valid evidence of incomplete work, not a
training dataset.

The next authorized operator must process the pending queue without changing
its hashes and emit candidate-source JSONL through the existing strict
protocol. Two distinct humans then label each candidate independently without
seeing one another's labels. Disagreement or either `uncertain` result goes to
a third, independent adjudicator. A new freeze may be called real and trainable
only after the validators close every gate.

## Offline example

The bundled `verifier_training/examples/corpus/` records are synthetic. They
exercise independent agreement, disagreement plus adjudication, repository
splits, and deterministic freeze hashes. Their manifest intentionally remains
non-trainable because only three of 29 synthetic PR sources have candidates.

The adjacent `verifier_training/corpus-snapshot/` directory is different: it
contains the real, sanitized public source identities and aggregate acquisition
manifest, but deliberately contains no candidate or label text.

Validate the complete source/candidate/annotation chain:

```powershell
.venv\Scripts\python.exe verifier_corpus.py validate `
  --plan verifier_training\corpus-plan.json `
  --pr-sources verifier_training\examples\corpus\pr-sources.jsonl `
  --candidate-sources verifier_training\examples\corpus\candidate-sources.jsonl `
  --annotations verifier_training\examples\corpus\annotations.jsonl
```

Rebuild the deterministic synthetic freeze:

```powershell
.venv\Scripts\python.exe verifier_corpus.py freeze `
  --plan verifier_training\corpus-plan.json `
  --pr-sources verifier_training\examples\corpus\pr-sources.jsonl `
  --candidate-sources verifier_training\examples\corpus\candidate-sources.jsonl `
  --annotations verifier_training\examples\corpus\annotations.jsonl `
  --frozen-at 2026-07-19T02:00:00Z `
  --candidates-out verifier_training\examples\corpus\frozen-candidates.jsonl `
  --splits-out verifier_training\examples\corpus\frozen-splits.json `
  --manifest-out verifier_training\examples\corpus\freeze-manifest.json
```

Run the focused regression gates:

```powershell
.venv\Scripts\python.exe -m unittest tests.test_verifier_corpus -v
.venv\Scripts\python.exe -m ruff check verifier_corpus.py tests\test_verifier_corpus.py
```

No command in this guide reads protected evaluation fixtures. Phase 8C's
separate synthetic-only runner is documented in `docs/verifier-transformer.md`.
